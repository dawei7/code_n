## General

**Count by deciding what happens to one distinguished element.** Let $D(i)$ be the number of derangements of `1..i`. Focus on element 1. It cannot remain in position 1, so choose some other position originally belonging to element `x`. There are `i-1` choices for `x`.

After placing 1 in `x`'s original position, there are two disjoint possibilities for element `x`:

1. `x` goes into position 1. Then 1 and `x` form a two-element swap, and the remaining `i-2` elements must be deranged among their remaining positions. This contributes $D(i-2)$ possibilities.
2. `x` does not go into position 1. Treating position 1 as the one forbidden destination for `x` reduces the remaining assignment to the same structural derangement problem on `i-1` items. This contributes $D(i-1)$ possibilities.

For each of the `i-1` choices of `x`, the cases are exhaustive and do not overlap. Therefore,

$$
D(i)=(i-1)\bigl(D(i-1)+D(i-2)\bigr).
$$

**Establish the base cases.** There is one permutation of zero elements—the empty permutation—and it vacuously fixes no element, so $D(0)=1$. A one-element array has only its original order, which fixes that element, so $D(1)=0$.

Although the public constraint begins at `n = 1`, storing $D(0)$ is necessary for the recurrence at `i = 2`:

$$
D(2)=1\cdot(D(1)+D(0))=1.
$$

That single derangement is `[2,1]`.

**Fill the recurrence bottom-up.** The exact source creates

`f = [1] + [0] * n`.

Thus `f[0]` is 1 and `f[1]` is already 0 whenever `n >= 1`. For each `i` from 2 through `n`, it evaluates the recurrence using the two previously completed entries:

`f[i] = (i - 1) * (f[i - 1] + f[i - 2]) % mod`.

For `n = 3`:

- `f[0] = 1`;
- `f[1] = 0`;
- `f[2] = 1`;
- `f[3] = 2 * (1 + 0) = 2`.

The two size-3 derangements are `[2,3,1]` and `[3,1,2]`.

**Why the recurrence counts every derangement exactly once.** Any derangement has one definite destination for element 1, identifying a unique `x` among the `i-1` choices. It then belongs to exactly one of the two cases depending on whether `x` occupies position 1. Reversing the construction recovers the smaller derangement counted by $D(i-2)$ or $D(i-1)$. No result is omitted and no result can be generated by two different choices or cases. Induction from the base cases proves every `f[i]` is correct.

**Reduce after every transition.** Derangement counts are close to `i! / e` and become enormous. The required answer is modulo $10^9+7$. Addition and multiplication commute with modular reduction, so reducing each newly computed state preserves the final residue while keeping stored values bounded.

Python itself supports arbitrary-size integers, but early modulo still avoids needlessly large arithmetic and matches implementations in fixed-width languages.

**The table contains more history than the transition needs.** Only `f[i-1]` and `f[i-2]` are read for the next state. The exact source nevertheless stores every result from 0 through `n`, which makes the recurrence easy to inspect but is not constant-space dynamic programming.

At the start of iteration `i`, every entry through `f[i - 1]` is already final and reduced modulo `mod`. The assignment reads only those completed states and writes a previously unused slot `f[i]`. This left-to-right invariant prevents a new value from contaminating either predecessor and is why no second table is necessary.

## Complexity detail

The loop performs one constant-time recurrence update for every `i` from 2 through `n`, so time complexity is $O(n)$. Allocating and retaining `f` with `n+1` entries uses $O(n)$ auxiliary space.

The manifest lists $O(n)$ time and $O(1)$ space. The time claim matches the exact source, but the space claim describes the editorial's rolling two-variable optimization, not this list-based implementation. Replacing the table with two previous values would attain $O(1)$ auxiliary space without changing the recurrence.

At the maximum `n = 10^6`, the difference is material: the list holds one million-plus references and modular integer objects. There is no recursion, so stack depth is constant.

## Alternatives and edge cases

- **Rolling two-state DP:** Keep only $D(i-2)$ and $D(i-1)$, compute the next value, and shift them. This matches the manifest's $O(1)$ space.
- **Memoized recursion:** It uses the same recurrence but needs $O(n)$ memo and call-stack space and risks recursion failure for large `n`.
- **Inclusion-exclusion formula:** Evaluate $n!\sum_{j=0}^{n}(-1)^j/j!$ modulo the prime. It is mathematically direct but easier to implement incorrectly.
- **`n = 1`:** The loop does not run and `f[1]` correctly returns 0.
- **`n = 2`:** The recurrence returns 1 for the single swap.
- **Empty-set base:** $D(0)=1$ is not a public query here but is essential to calculate $D(2)$.
- **Large `n`:** Iteration avoids recursion depth, while per-step modulo controls integer size.
- **Modulo placement:** Apply it after multiplication and addition at every state; delaying it is unnecessary.
- **No fixed positions:** A permutation with even one element in its original index must not be counted.
- **Manifest mismatch:** The literal `f` list is $O(n)$ space; only the rolling alternative is $O(1)$.
