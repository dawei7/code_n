## General

**Treat every complete grid distribution as a search state.** The grid is always three by three and contains exactly nine indistinguishable stones. One legal move changes two adjacent cell counts: the source decreases by one and the destination increases by one.

Every move has the same cost of one, so breadth-first search over configurations finds the minimum number of moves.

**Use immutable tuples as state keys.** The starting grid is converted to a tuple of row tuples. This representation is hashable and can be stored in `vis`. A mutable list of lists could not safely serve as a set key.

The queue starts with the initial state, and `ans` starts at zero.

**Process one BFS distance layer at a time.** The outer infinite loop takes the current queue length and processes exactly those states. They are all reachable in `ans` moves. Newly generated states enter the queue for the next layer. After the layer, `ans` increments.

Therefore, the first goal state encountered has the smallest possible number of moves.

**Recognize the goal through positivity.** The test

`all(x for row in cur for x in row)`

checks that every cell has at least one stone. Counts are never negative, and the total remains nine. With nine cells and nine total stones, having every cell positive implies every cell has exactly one. Thus the test is equivalent to the required final distribution.

**Generate moves only from surplus cells.** The source considers a cell when `cur[i][j] > 1`. One stone in every occupied cell can be regarded as its permanent final stone; only stones beyond the first need transport. Moving the only stone out of a cell would create a new empty demand and is never necessary in an optimal transport interpretation.

**Move to an adjacent cell with fewer than two stones.** The four direction pairs come from `pairwise(dirs)`. A valid destination is in bounds and has count below two. After receiving a stone, it has at most two.

This restriction keeps states compact. A destination with zero becomes satisfied. A destination with one becomes a temporary two-stone cell whose surplus can continue moving on a later step. Transport through an occupied cell is therefore possible: add the mobile stone to make two, then move one onward.

The code does not move directly into a cell already holding two or more stones. Such extra stacking can be avoided by moving an existing surplus onward first; reordering these unit transports preserves or improves the number of moves in this small connected grid.

**Create one independent successor.** For each move, the tuple state is copied to lists, source and destination counts are changed, and the result is converted back to tuples. The current state is never mutated in place, so other neighbor branches remain correct.

If the successor has not appeared before, it is marked visited immediately and enqueued. Marking on enqueue prevents the same configuration from occupying the queue multiple times through different move sequences.

**Why BFS proves minimality.** Every queue edge represents exactly one allowed side-adjacent stone move. Conversely, every move generated by the restricted surplus-transport model leads to one neighbor state. BFS explores configurations in nondecreasing path length from the start. When the all-one distribution is popped, `ans` is the length of a shortest move sequence reaching it.

**The finite state space guarantees termination for valid inputs.** A distribution of nine indistinguishable stones among nine cells has at most

$$
\binom{17}{8}=24{,}310
$$

possible nonnegative configurations before applying the source's additional transition restrictions. The three-by-three grid is connected, so a valid all-one distribution is reachable. The unbounded-looking `while 1` therefore eventually returns under the problem contract.

**The exact algorithm differs from the manifest.** The manifest describes matching surplus stones to empty cells with subset DP in $O(k2^k)$ time. The source performs BFS over full grid configurations. Its appropriate complexity is expressed in terms of reachable state count, not a destination mask.

## Complexity detail

Let $S$ be the number of configurations reachable under the source's transitions. Each state is enqueued at most once. Processing it scans nine cells and at most four neighbors per surplus cell. Copying a state also touches nine counts. Since nine and four are fixed, time is $O(S)$.

The queue and visited set can store $O(S)$ states, each of fixed nine-cell size, so space is $O(S)$.

For this fixed problem, $S$ is bounded above by 24,310, making both bounds effectively constant with respect to an external input-size parameter. It is still more informative to state the state-space bound than merely say $O(1)$.

The manifest's $O(k2^k)$ time and $O(2^k)$ space belong to the absent surplus-to-empty assignment DP.

## Alternatives and edge cases

- **Subset assignment DP:** List each extra stone's source coordinate and each empty destination, then minimize total Manhattan matching cost over destination masks. It gives $O(k2^k)$ time and $O(2^k)$ space and matches the manifest.
- **Enumerate permutations of assignments:** With at most eight empty cells this can work, but subset DP avoids repeated subproblems.
- **Already balanced grid:** The initial state passes the goal test and returns zero.
- **One distant empty cell:** A surplus stone can traverse through one-stone cells by temporarily making them two.
- **Multiple stones in one cell:** Every count beyond one is independently movable surplus.
- **Total-stone invariant:** Every successor subtracts and adds one, so total always remains nine.
- **Goal positivity:** It implies exactly one per cell only because total stones and cell count are both nine.
- **Visited timing:** Marking on enqueue avoids duplicate work while preserving BFS shortest distances.
- **Immutable state:** Tuple conversion is required for reliable hashing.
- **Queue exhaustion outside the contract:** The infinite outer loop has no empty-queue guard; it relies on guaranteed reachability and the adequacy of the restricted transitions.
- **Manifest mismatch:** The exact solution searches distributions rather than solving an explicit Manhattan assignment DP.
