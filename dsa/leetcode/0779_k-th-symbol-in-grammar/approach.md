## General

**Do not construct the exponentially long row**

Row one contains `0`. Every `0` becomes `01` and every `1` becomes `10`. The length doubles at every step, so row `n` contains $2^{n-1}$ symbols.

Building that row would spend exponential time and space even though the method needs only one position. The recursive solution instead determines which half contains position `k` and maps that position back into the preceding row.

**Derive the two-half structure**

Suppose some preceding row is a sequence `S`. Expanding every bit produces the next row. The first output bit generated by a source bit is that same bit, while the second output bit is its opposite.

Across a complete row, this gives a useful equivalent pattern: row `n` consists of row `n - 1` followed by the bitwise complement of row `n - 1`.

For example:

- Row one is `0`.
- Row two is `0 | 1`.
- Row three is `01 | 10`.
- Row four is `0110 | 1001`.

The vertical bar marks equal-length halves. The left half repeats the previous row, and the right half is its complement.

**Find the half boundary without creating a row**

Row `n` has $2^{n-1}$ symbols, so either half has $2^{n-2}$ symbols. The expression `1 << (n - 2)` computes exactly that power of two.

Positions are one-indexed:

- If $k \le 2^{n-2}$, position `k` lies in the left half.
- If $k > 2^{n-2}$, it lies in the right half.

The equality belongs to the left half because $2^{n-2}$ is the last left-half position, not the first right-half position.

**Map a left-half position to the smaller problem**

The left half of row `n` is identical to row `n - 1`. Therefore the symbol at `(n, k)` is exactly the symbol at `(n - 1, k)` when `k` is within the first half.

The solution makes that recursive call without changing `k`:

`kthGrammar(n - 1, k)`.

This discards half of the conceptual row and one row level without performing any replacements.

**Map a right-half position and flip**

For a right-half position, subtract the half length to obtain the corresponding one-indexed position in the previous row:

$$
k' = k - 2^{n-2}.
$$

The right half is the complement of the previous row, so the required answer is the opposite of the recursive result at `(n - 1, k')`. Because a grammar symbol is either zero or one, XOR with one performs that flip: `0 ^ 1 = 1` and `1 ^ 1 = 0`.

That is why the final branch is

`kthGrammar(n - 1, k - half) ^ 1`.

The XOR happens while recursion unwinds. If the path enters right halves several times, the result flips once for each such choice; an even number of flips returns to the original bit, while an odd number produces its opposite.

**Base case**

When `n == 1`, the row contains only the known symbol zero. The only valid position is one, so the method returns zero directly.

Every recursive call reduces `n` by one. The position passed to the next call always lies within the shorter row: it stays unchanged when it was in the left half and has exactly one half length removed when it was in the right half. Recursion must therefore reach this valid base case.

**Trace row four, position five**

Row four is `01101001`, and its fifth symbol is one. The algorithm reaches the same answer without generating the string.

The half length at row four is four. Since `k = 5` is in the right half, it maps to row three, position one, and records one flip.

At row three, position one is in the left half, so it maps to row two, position one unchanged. The same occurs from row two to row one. Row one returns zero. Unwinding the recorded right-half step flips zero to one.

**Why the recursion is correct**

Use induction on `n`. For `n = 1`, the direct return is the sole row symbol and is correct.

Assume recursive answers are correct for row `n - 1`. A position in row `n` lies in exactly one of its two halves. In the left half, the row structure says its symbol equals the same position in row `n - 1`, which the first recursive branch returns correctly. In the right half, the row structure says its symbol is the complement of the corresponding previous-row position; the second branch finds that correct previous symbol by induction and XORs it with one. Both possible positions are therefore handled correctly, completing the induction.

**What role `n` still plays**

The value `n` determines how wide the current row and half are. Once the position is valid for that row, the final bit can also be characterized by the parity of set bits in `k - 1`, but the exact implementation does not use that shortcut. It explicitly descends one row at a time.

## Complexity detail

The exact Python solution performs one recursive call for every row from `n` down to one. Each call does constant arithmetic and one comparison, so its actual time complexity is $O(n)$.

There are $O(n)$ simultaneously active recursion frames before the base case returns, so its auxiliary space is $O(n)$.

The current optimal manifest lists $O(\log k)$ time and $O(1)$ space. Those bounds describe the bit-parity formulation when set-bit parity is computed iteratively under the usual word model; they do not describe this exact recursive source. In particular, `k` may equal one while `n` grows, and this implementation still makes `n - 1` recursive calls. Accuracy requires keeping this distinction explicit rather than attributing the alternative's bounds to the displayed code.

## Alternatives and edge cases

- **Set-bit parity of `k - 1`:** The answer equals the parity of the number of one bits in `k - 1`. Kernighan's bit-clearing loop can compute it in $O(\log k)$ worst-case time and $O(1)$ space, matching the manifest bounds.

- **Iterative half descent:** Repeat the same left/right decisions while decreasing `n` and toggle a bit on every right-half step. It preserves $O(n)$ time but removes recursion-stack space.

- **Generate every row:** This is easy to visualize but requires $O(2^n)$ total work and $O(2^{n-1})$ space for the final row.

- **First row:** `n = 1` returns zero immediately.

- **First position:** `k = 1` always stays in left halves and eventually returns zero.

- **Last left-half position:** The test uses `<=`, so the boundary is not incorrectly treated as complemented.

- **First right-half position:** Subtracting the half length maps it to position one of the preceding row before flipping.

- **Repeated right-half choices:** Every choice contributes one XOR; XOR naturally keeps only whether the number of flips is odd or even.

- **One-indexing:** Subtracting the half length preserves one-indexing. Converting to zero-based indexing would change the formulas and is a common source of off-by-one errors.
