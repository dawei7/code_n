## General

**Solve one element before solving the array.** An operation changes exactly one chosen element by exactly $1$: it either adds $1$ or subtracts $1$. Whether one element is divisible by $3$ has no effect on any other element, and an operation cannot improve two positions simultaneously. Therefore the global minimum is the sum of the independent minimum costs for the individual values.

Every integer belongs to exactly one of three remainder classes when divided by $3$:

$$
x\bmod 3\in\{0,1,2\}.
$$

Those three cases completely determine the answer for one positive value.

If $x\bmod 3=0$, then $x$ is already divisible by $3$. It needs zero operations.

If $x\bmod 3=1$, subtracting one produces $x-1$, whose remainder is zero. Thus one operation is sufficient.

If $x\bmod 3=2$, adding one produces $x+1$. Advancing the remainder from $2$ to the next multiple of $3$ also takes one operation. Equivalently, subtracting twice would work, but that is not minimal.

So every non-divisible value needs exactly one operation. This simplification is special to modulus $3$: the only nonzero remainders, $1$ and $2$, are each one step from a multiple, but in opposite directions.

**Why one operation is also necessary.** It is not enough to show a construction with one operation; minimum claims need a lower bound. If $x\bmod 3\ne0$, doing zero operations leaves $x$ unchanged and therefore still not divisible by $3$. At least one operation is unavoidable. The case analysis above gives a legal one-operation change, so the minimum is exactly one.

We may summarize the per-element cost as the indicator

$$
[x\bmod 3\ne0],
$$

which equals $1$ when the condition is true and $0$ otherwise. The array answer is

$$
\sum_{x\in\texttt{nums}}[x\bmod 3\ne0].
$$

**Read the one-line Python implementation literally.** The exact source returns

`sum(x % 3 != 0 for x in nums)`.

For each `x`, `x % 3 != 0` evaluates to the Boolean value `True` if the remainder is nonzero and `False` otherwise. In Python, `bool` is a subclass of `int`: `True` contributes $1$ to `sum` and `False` contributes $0$. The generator does not build a separate list. It produces one Boolean at a time, and `sum` accumulates the count.

The expression is therefore not merely a shortcut that happens to pass the examples. It is a direct implementation of the proved formula: count exactly those array elements whose independent minimum cost is one.

**Why choices never interfere.** Suppose there are $k$ non-divisible elements. Each needs at least one operation, and a single operation touches only one array position, so any complete process uses at least $k$ operations. For each of those $k$ positions, use the one-step correction determined by its remainder: subtract one for remainder $1$, add one for remainder $2$. This constructs a complete process using exactly $k$ operations. The lower and upper bounds agree, proving that the returned count is globally minimal.

For `nums = [1, 2, 3, 4]`, the remainders are `[1,2,0,1]`. The Boolean sequence generated by the source is `[True, True, False, True]` conceptually, although no list is actually allocated. Its sum is three. One possible realization subtracts one from $1$, adds one to $2$, leaves $3$ alone, and subtracts one from $4$.

For `nums = [3, 6, 9]`, every remainder is zero. All generated Booleans are false, their sum is zero, and doing nothing is both sufficient and necessarily minimal.

**The returned number does not prescribe a unique operation sequence.** A remainder-$1$ value can be reduced once for the shortest change; a remainder-$2$ value can be increased once. Other, longer sequences can also reach a multiple, such as increasing a remainder-$1$ value twice, but the problem asks only for the minimum count. The implementation correctly returns that count without modifying `nums` or constructing the operations themselves.

## Complexity detail

Let $n$ be the number of elements in `nums`. The generator visits each element exactly once. Computing a remainder, comparing it with zero, and adding a Boolean to the running total are constant-time operations for the bounded integers in the problem. Total time is therefore $O(n)$. This is asymptotically optimal because every input element can independently be divisible or non-divisible; an exact algorithm must inspect all $n$ values in the worst case.

The generator expression is lazy. It does not allocate an $n$-element array of remainders or Boolean flags. At any instant, it holds the current element and the accumulator, so auxiliary space is $O(1)$. The input array is read only, and the returned integer is output rather than auxiliary storage.

The constraints cap values at $50$, so integer arithmetic is trivially constant cost. Even in Python's more general arbitrary-precision model, this stated-domain analysis is exact. The manifest's $O(n)$ time and $O(1)$ space describe the source precisely.

## Alternatives and edge cases

- **Explicit loop and counter:** Initialize `operations = 0`, inspect each remainder, and increment for nonzero ones. This has the same optimal bounds and may be easier to debug, but the generator-based sum expresses the indicator count more compactly.
- **Editorial distance formula:** The general per-value formula is `min(x % 3, 3 - x % 3)`. For remainders $0$, $1$, and $2$, it evaluates to $0$, $1$, and $1$, so it is equivalent here. The exact source uses the simpler nonzero-remainder indicator.
- **Actually mutate every number:** Applying the chosen additions and subtractions would produce a valid final array, but the requested output is only the minimum count. Mutation adds work and risks changing caller data without providing useful information.
- **Repeated operations until divisible:** A loop that increments or decrements one step at a time can eventually work, but recognizing the three remainder cases proves that at most one operation is ever needed and eliminates needless simulation.
- **Already divisible values:** They contribute zero. Performing an operation on one would make it non-divisible, so touching it cannot belong to a minimum solution.
- **Remainder one:** Subtract exactly one. Adding one leaves remainder two and adding two would take more operations.
- **Remainder two:** Add exactly one. Subtracting one leaves remainder one and subtracting two would take more operations.
- **Array of length one:** The Boolean sum returns either zero or one, exactly matching the single-element case.
- **Every element divisible:** The generator yields only `False`, and `sum` returns zero without a special branch.
- **No element divisible:** Every generated Boolean is `True`, so the answer is `len(nums)`. Each position needs its own operation because operations cannot affect multiple elements.
- **Duplicate values:** Each array occurrence is a separate element and must be made divisible independently. The source correctly counts every occurrence rather than every distinct value.
- **Positive-input guarantee:** The stated constraints contain only positive integers. Python's modulo would still give a remainder in `{0,1,2}` for negative values, and the nonzero-count conclusion remains valid because both addition and subtraction are allowed, but that extension is not needed for the contract.
- **No input mutation:** Unlike solutions that demonstrate the changes, this method only reads `nums`. The caller's array remains in its original form.
- **Why modulus matters:** For divisibility by $m>3$, a nonzero remainder can be more than one step from either neighboring multiple. Merely counting nonzero remainders would then undercount. The one-operation result relies specifically on the two nonzero classes modulo three.
