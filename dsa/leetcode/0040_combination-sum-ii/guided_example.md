# Guided Example: Combination Sum II

We trace the step-by-step recursive backtracking decision tree with duplicate sibling pruning on a representative candidate array:

- **Input:** $\text{candidates} = [10, 1, 2, 7, 6, 1, 5]$, $\text{target} = 8$
- **Required output:** `[[1, 1, 6], [1, 2, 5], [1, 7], [2, 6]]`

This instance demonstrates sorting, one-time candidate consumption via index advancement ($j + 1$), distinguishing vertical repetition (valid) from horizontal sibling repetition (duplicate), and early-pruning of infeasible branches.

---

## 1. Instance & Teaching Goal

Given a collection of candidate numbers $\text{candidates} = [10, 1, 2, 7, 6, 1, 5]$ containing duplicates, and a target integer $\text{target} = 8$, we must find all unique combinations summing to $8$. Each number in $\text{candidates}$ may be used **only once** per combination.

The input array sorted in ascending order is:
$$
[1, 1, 2, 5, 6, 7, 10]
$$

Notice the duplicate value $1$ appears at index 0 and index 1:
- Choosing index 0 then index 1 produces $[1, 1, 6]$ (valid vertical reuse of identical distinct numbers).
- Choosing index 0 then index 5 produces $[1, 7]$. Choosing index 1 then index 5 also produces $[1, 7]$.
- To prevent producing $[1, 7]$ twice, the algorithm must prune duplicate sibling branches at the same tree depth.

---

## 2. Conceptual Foundation & Invariants

### Horizontal Duplicate Pruning vs Vertical Reuse
After sorting $\text{candidates}$:
1. **One-Time Consumption:** When an element at index $j$ is chosen, the recursive call advances to $j + 1$:
   $$
   \text{backtrack}(j + 1, \text{remain} - \text{candidates}[j])
   $$
   This ensures no single array index is selected more than once.
2. **Sibling Duplicate Pruning:** Within the same loop over $j \in [\text{start\_idx}, N - 1]$:
   - If $j > \text{start\_idx}$ and $\text{candidates}[j] == \text{candidates}[j-1]$, we execute `continue`.
   - **Why this works:** When $j = \text{start\_idx}$, we explore all combinations that use this value as the first choice at the current depth (including downstream paths that might also pick its duplicates at $j+1$). When $j > \text{start\_idx}$ and $\text{candidates}[j] == \text{candidates}[j-1]$, starting a new branch with the second identical element would only generate an exact subset of the combinations already generated by the first element.
3. **Early Break on Overflow:** Because the array is sorted, if $\text{candidates}[j] > \text{remain}$, we execute `break` immediately.

> **Invariant.** All combinations are generated in canonical non-decreasing index order. Sibling pruning guarantees that each unique multiset combination is emitted exactly once.

---

## 3. Step-by-Step Worked Execution

We trace sorted array $[1, 1, 2, 5, 6, 7, 10]$ with $\text{target} = 8$:

### Level 0: Root State $(\text{start} = 0, \text{remain} = 8)$

#### Branch 1: Choose $1$ (Index 0)
- Current path: $[1]$, $\text{remain} = 7$. Recurse with $\text{start} = 1$:
  - Choose $1$ (Index 1): path $[1, 1]$, $\text{remain} = 6$. Recurse with $\text{start} = 2$:
    - $j=2$ ($2$): path $[1, 1, 2]$, $\text{remain} = 4$. Remaining elements $[5, 6, 7, 10] > 4 \implies$ all pruned.
    - $j=3$ ($5$): $5 > 6 - 2$? Check: $j=3$ gives path $[1, 1, 5]$, $\text{remain} = 1 < 6 \implies$ pruned.
    - $j=4$ ($6$): path $[1, 1, 6]$, $\text{remain} = 6 - 6 = 0$.
      - **Match 1: `[1, 1, 6]`!**
  - Choose $2$ (Index 2): path $[1, 2]$, $\text{remain} = 5$. Recurse with $\text{start} = 3$:
    - $j=3$ ($5$): path $[1, 2, 5]$, $\text{remain} = 5 - 5 = 0$.
      - **Match 2: `[1, 2, 5]`!**
    - $j=4$ ($6$): $6 > 5 \implies$ break (prune).
  - Choose $5$ (Index 3): path $[1, 5]$, $\text{remain} = 2$. Smallest next is $6 > 2 \implies$ break.
  - Choose $6$ (Index 4): path $[1, 6]$, $\text{remain} = 1$. Smallest next is $7 > 1 \implies$ break.
  - Choose $7$ (Index 5): path $[1, 7]$, $\text{remain} = 0$.
    - **Match 3: `[1, 7]`!**
  - Choose $10$ (Index 6): $10 > 7 \implies$ break.

---

#### Branch 2: Index 1 (Value $1$) at Level 0
- Loop index $j = 1 > \text{start} = 0$, and $\text{candidates}[1] == \text{candidates}[0] == 1$.
- **Duplicate sibling detected!** Skip $j = 1$ via `continue`.
- *(Prevents duplicate generation of $[1, 7]$, $[1, 2, 5]$, etc.)*

---

#### Branch 3: Choose $2$ (Index 2)
- Current path: $[2]$, $\text{remain} = 8 - 2 = 6$. Recurse with $\text{start} = 3$:
  - $j=3$ ($5$): path $[2, 5]$, $\text{remain} = 1$. Next is $6 > 1 \implies$ break.
  - $j=4$ ($6$): path $[2, 6]$, $\text{remain} = 6 - 6 = 0$.
    - **Match 4: `[2, 6]`!**
  - $j=5$ ($7$): $7 > 6 \implies$ break.

---

#### Branch 4: Choose $5$ (Index 3)
- Current path: $[5]$, $\text{remain} = 8 - 5 = 3$. Smallest next candidate is $6 > 3 \implies$ break.

#### Remaining Branches ($6, 7, 10$)
- All candidates $\ge 6$ either have insufficient room or exceed target.

Final output: `[[1, 1, 6], [1, 2, 5], [1, 7], [2, 6]]`.

---

## 4. Complete Execution Trace

| Level 0 Choice | Sub-Level Choices | Full Candidate Path | Path Sum | Condition Met | Output Emitted / Status |
|:---:|:---:|:---:|:---:|:---:|:---|
| $1$ (idx 0) | $1$ (idx 1) $\to 6$ (idx 4) | `[1, 1, 6]` | 8 | $\text{remain} = 0$ | **`[1, 1, 6]`** |
| $1$ (idx 0) | $2$ (idx 2) $\to 5$ (idx 3) | `[1, 2, 5]` | 8 | $\text{remain} = 0$ | **`[1, 2, 5]`** |
| $1$ (idx 0) | $7$ (idx 5) | `[1, 7]` | 8 | $\text{remain} = 0$ | **`[1, 7]`** |
| $1$ (idx 1) | - | - | - | $j > \text{start} \land \text{val} == \text{prev}$ | **Skipped (Duplicate Sibling)** |
| $2$ (idx 2) | $6$ (idx 4) | `[2, 6]` | 8 | $\text{remain} = 0$ | **`[2, 6]`** |
| $5$ (idx 3) | - | `[5]` | 5 | Next candidate $6 > 3$ | Pruned |

---

## 5. Algorithmic Correctness

**Soundness.** Every emitted combination sums to $\text{target}$. Advancing the recursion index to $j + 1$ ensures no array element is selected more than once.

**Completeness.** Sorting guarantees that identical values are adjacent. Skipping $\text{candidates}[j] == \text{candidates}[j-1]$ only when $j > \text{start\_idx}$ allows the first copy of any duplicate number to explore all combinations containing any number of identical duplicates, while strictly preventing duplicate parallel branches. Thus, all valid multiset combinations are discovered without repetition.

---

## 6. Traps This Instance Exposes

- **Skipping All Duplicates (`j >= start`):** Writing `if candidates[j] == candidates[j-1]` without checking `j > start_idx` mistakenly prevents vertical reuse, missing valid combinations like $[1, 1, 6]$.
- **Shallow Reference Mutations:** Backtracking must create a shallow copy `current_combo[:]` when recording solutions to prevent subsequent pop operations from clearing the result.
- **Missing Break on Overflow:** Because candidates are sorted, once $\text{candidates}[j] > \text{remain}$, all subsequent $k > j$ will also exceed $\text{remain}$. Breaking the loop instead of continuing saves exponential search steps.

---

## 7. Complexity Derivation

- **Time Complexity:** $O(2^N)$, where $N$ is the number of candidates. In the worst case, every element can either be included or excluded. Sorting takes $O(N \log N)$, and early pruning significantly reduces the visited subtree count in practice.
- **Auxiliary Space Complexity:** $O(N)$ for recursion call stack depth and storing combination results.
