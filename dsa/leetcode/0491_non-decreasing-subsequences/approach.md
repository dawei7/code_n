## General

A subsequence keeps the original index order but may skip any elements. At each index there are normally two choices: include the value or exclude it. That creates a binary recursion tree covering all index subsequences. Two extra requirements shape this solution: included values must be non-decreasing, and equal value sequences must appear only once even when duplicate input positions could produce them.

`dfs(u, last, t)` carries three pieces of state:

- `u` is the next input index to decide;
- `last` is the last value already placed in the subsequence;
- `t` is the current subsequence itself.

The initial call uses `u = 0`, an empty list, and `last = -1000`. Since input values are at least `-100`, every possible first value is greater than this sentinel. It behaves like negative infinity without requiring a special “list is empty” branch.

**Include only when order remains legal.** If `nums[u] >= last`, appending the current value preserves non-decreasing order. Equality is allowed; the problem says non-decreasing, not strictly increasing. The code appends `nums[u]`, recursively processes the next index with that value as the new `last`, and then pops it.

The pop is backtracking. Every recursive call shares the same mutable list `t`. After the include branch returns, removing the last element restores exactly the list that existed before the choice, allowing the exclude branch and later calls to start from the correct prefix.

If `nums[u] < last`, inclusion is forbidden because it would introduce a decrease. The include branch is skipped, but excluding the element may still allow later, larger values to extend the subsequence.

**The unusual exclude condition removes duplicates.** A naive include/exclude recursion can generate the same value sequence from different equal-valued positions. The source prevents that without a global set using

`if nums[u] != last: dfs(u + 1, last, t)`.

When `nums[u] == last`, inclusion is legal, but exclusion is suppressed. Why is that safe? The current subsequence already ends with an equal value selected from an earlier index. If the algorithm skipped the current equal occurrence and later appended some suffix, the same value sequence can be represented canonically by skipping the earlier equal occurrence and choosing the current one instead, followed by that identical suffix. The indices differ, but the requested output consists of values, so those are duplicates.

For a concrete example, consider the two final sevens in `[4, 6, 7, 7]`. After choosing the first seven, the next value equals `last`. Including it is necessary to generate `[4, 6, 7, 7]`. Skipping it would eventually generate `[4, 6, 7]`, but that sequence is already generated by skipping the first seven and choosing the second. Suppressing the skip branch at equality keeps the longer repeated-value option while avoiding the duplicate shorter sequence.

When `nums[u] != last`, excluding it is necessary. The current value cannot simply stand in for the previously selected last value, because the value sequences would differ. Both legal inclusion and exclusion must then be explored.

This rule gives each distinct value subsequence a canonical index realization. Informally, when equal interchangeable positions could represent the same final sequence, the search commits to one consistent placement instead of enumerating them all. Unlike a per-depth `used` set, it relies on the relation between the current input value and the last selected value, matching the exact source.

**Record only complete decisions.** When `u == len(nums)`, every input position has been included or excluded. If `len(t) > 1`, the code appends `t[:]` to `ans`. The slice is essential: appending `t` itself would store a reference to the mutable backtracking list, and later pops would change every recorded answer. A copy preserves the completed sequence.

Length zero and length one subsequences are discarded at the leaf because the contract requires at least two elements. Recording only at leaves also prevents the same current prefix from being appended once at every later skipped position.

Correctness has three parts. First, every produced list respects input order because indices are processed strictly from left to right. Second, inclusion is allowed only at `nums[u] >= last`, so every produced list is non-decreasing. Third, every valid distinct value subsequence has at least one path through the choices, while the equality skip rule removes alternative paths that differ only in which interchangeable equal index was used. Hence the final list contains all and only the required distinct subsequences.

For `[4, 4, 3, 2, 1]`, the two fours can form `[4, 4]`. After that, every remaining value is smaller than `last = 4`, so no extension is legal. Paths that select only one four are discarded for being too short, and the result contains exactly the repeated pair.

## Complexity detail

Let $n$ be the input length. The decision tree has at most $2^n$ leaves and $O(2^n)$ states before pruning. Copying a completed subsequence costs up to $O(n)$, so total time is $O(n2^n)$. This is appropriate because the output itself can contain exponentially many sequences with linear total length per sequence.

The answer occupies $O(n2^n)$ space in the worst case. Excluding output, recursion depth is $O(n)$ and the working list holds at most $n$ values, for $O(n)$ auxiliary space. The manifest includes output storage and records $O(n2^n)$ space.

## Alternatives and edge cases

- **Backtracking plus a global set:** Generate every legal index subsequence, convert each result to a tuple, and deduplicate. It is easier to derive but spends time and memory constructing duplicate paths.
- **Per-recursion-level used set:** At one depth, skip trying the same value twice as the next appended element. This is another standard duplicate-control method and can be easier to prove locally.
- **Bitmask enumeration:** Iterate through all $2^n$ subsets of indices, build each sequence, test non-decreasing order, and insert tuples into a set. It has similar asymptotic cost but less direct pruning.
- **Equal adjacent values:** Equality is legal for non-decreasing order. The include branch must use `>=`, not `>`.
- **Strict decrease:** A smaller current value cannot be included, but the exclude branch continues searching later positions.
- **Sentinel safety:** `-1000` is below the guaranteed minimum `-100`. If the value constraints changed, a true negative-infinity sentinel would be safer.
- **Mutable result aliasing:** `t[:]` must be stored. Appending `t` would let later backtracking mutate previously recorded answers.
- **Fewer than two elements:** The leaf check excludes the empty sequence and every singleton, even though both are vacuously non-decreasing.
