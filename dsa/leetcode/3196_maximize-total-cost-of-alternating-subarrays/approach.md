## General

**View a partition as a sequence of signs.** Every subarray contributes its first element positively, its second negatively, its third positively, and so on. When a new subarray begins, the sign resets to positive. Across the whole array, this means:

- the first element must be added;
- after an added element, the next element may be subtracted by continuing the current subarray, or added by cutting before it;
- after a subtracted element, the next element must be added. Continuing alternation gives a plus, and starting a new subarray also gives a plus.

So the global sign sequence begins with plus and can never contain two consecutive minus signs. Choosing the best partition is equivalent to choosing the maximum-value valid sign sequence.

**Give the second state a concrete meaning.** The memoized function `dfs(i, j)` returns the maximum contribution obtainable from suffix `nums[i:]`, given whether position `i` is allowed to receive a minus sign.

- `j = 0` means minus is not allowed. The current value must be added.
- `j = 1` means both choices are legal: add the value by starting a new subarray here, or subtract it by continuing after a preceding plus.

The initial call is `dfs(0, 0)` because the first element of the first subarray must be positive.

The state can also be understood through the preceding sign. After choosing plus, the next element is allowed to be minus, so the recursive call uses state $1$. After choosing minus, the next element must be plus, so the call uses state $0$.

**Derive the two transitions.** Adding the current value is always legal. It contributes `nums[i]` now, and a minus becomes legal at the next position:

`nums[i] + dfs(i + 1, 1)`.

This plus may mean continuing a subarray after a preceding minus, or starting a fresh subarray after a preceding plus. The numerical contribution is the same, so the state does not need to distinguish those histories.

Subtracting the current value is legal only when `j == 1`. It contributes `-nums[i]` and forces the next sign to plus:

`-nums[i] + dfs(i + 1, 0)`.

The function stores the plus branch in `ans` and, when allowed, replaces it with the larger of the plus and minus branches. At `i >= len(nums)`, no element remains, so the best suffix contribution is zero.

**Why no partition information is missing.** Any legal partition determines one allowed sign for each position. Its first sign is plus, and signs inside each subarray alternate. A cut resets the following sign to plus, so two minuses never occur consecutively. The recursion can reproduce that sign sequence: take its plus branch at every positive position and its conditional minus branch at every negative position.

Conversely, any sign sequence generated by the recursion can be realized by a partition. Begin the first subarray at index zero. Whenever a plus follows a plus, a cut is required before the second plus. Whenever a minus follows a plus, continue the current subarray. A plus after a minus may continue the alternation; choosing a cut there would produce the same signs and cost, so either interpretation is valid. Thus maximizing over recursive branches is exactly maximizing over possible partitions, even though several partitions can occasionally have the same sign sequence and total.

**Why the recurrence chooses an optimum.** Assume `dfs(i + 1, 0)` and `dfs(i + 1, 1)` already give optimal values for their suffix states. In state zero, every valid continuation must add `nums[i]`, so the sole branch is optimal. In state one, every valid continuation either adds or subtracts `nums[i]`; the two expressions use the optimal remaining value after each choice, so their maximum is optimal. The empty suffix base case is exact. Induction backward over `i` proves `dfs(0,0)` returns the maximum total cost.

**Trace the main example.** For `nums = [1,-2,3,4]`, the first $1$ must be added. At $-2$, subtracting it is attractive and contributes $2$, after which $3$ must be added. At $4$, the recursion may subtract it by continuing the same alternating subarray or add it by starting a new subarray. Adding is better. The selected signs are $+,-,+,+$, corresponding to subarrays `[1,-2,3]` and `[4]`, and the total is $1-(-2)+3+4=10$.

Negative values are exactly why both branches matter. Subtracting a negative number increases the score, but choosing minus also constrains the next position to plus. A locally attractive subtraction can therefore influence future choices; memoized dynamic programming evaluates the complete suffix consequence rather than applying an unproved local rule.

**Caching prevents exponential recomputation.** Without `@cache`, the plus and minus branches would repeatedly solve the same pair of states for later indices, producing an exponential recursion tree. The cache stores each reachable `(i,j)` result once. There are only two possible flags for every index.

## Complexity detail

Let $n$ be the array length. There are at most $2(n+1)$ memoization states. Each state performs constant arithmetic and at most two cached recursive calls, so total time is $O(n)$.

The cache stores $O(n)$ results. The active recursive call chain can also reach depth $n+1$, because every branch advances by one index before returning. Therefore the exact source uses $O(n)$ auxiliary space, not $O(1)$.

This is a material mismatch with the manifest, whose summary describes “two constant-space DP states” and whose space bound is $O(1)$. Those claims describe an iterative compression of this recurrence, not `solution.py`. The exact source is linear-time, linear-space memoized recursion.

The depth discrepancy is operationally important: the constraint allows $n=10^5$, far beyond Python's usual recursion limit. Caching removes repeated states but does not shorten the deepest chain, so a valid long input can raise `RecursionError`. An iterative two-state implementation is needed for robust support of the full stated domain.

## Alternatives and edge cases

- **Iterative two-state DP:** Maintain the best value for the “must add” and “may subtract” states while scanning. It implements the same recurrence in $O(n)$ time and $O(1)$ space, matches the manifest, and avoids recursion-depth failure.
- **Bottom-up array DP:** Store both states for every suffix from right to left. This remains $O(n)$ time and $O(n)$ space but avoids recursion and is often easier to inspect than a cache.
- **Enumerate every partition:** There are $2^{n-1}$ choices of cut boundaries. Direct enumeration repeats equivalent suffix decisions and is infeasible.
- **Always subtract a negative value:** This local rule is unsafe because a minus forces the next sign to plus. The DP compares the complete future value of continuing versus cutting.
- **All positive values:** Splitting every element into its own length-one subarray adds every value, so the answer is their sum. The recursion finds this through repeated plus choices.
- **All negative values:** The first value still must be added. Later negative values may profitably receive minus signs, but never consecutively; the DP selects the best allowed pattern.
- **Single element:** State `dfs(0,0)` must add it, and the suffix base contributes zero. The answer equals that element, including when it is negative.
- **Plus after minus:** It may represent continuing the current subarray or cutting before the current element. Both produce the same sign and score, so the state can merge them safely.
- **Plus after plus:** It necessarily represents a split, because an unsplit alternating subarray would require a minus.
- **Large totals:** With magnitude up to $10^9$ and $10^5$ elements, the result may exceed 32-bit range. Python integer arithmetic remains exact.
- **Input preservation:** The recursive solution only reads `nums` and does not reorder or mutate it.
- **Manifest mismatch:** Treat the source as $O(n)$ space and recursion-limited. Constant-space claims apply only to a different iterative implementation.
