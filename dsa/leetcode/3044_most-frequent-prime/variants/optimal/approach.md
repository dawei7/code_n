## General

**Enumerate exactly the permitted paths.** Associate the eight compass directions with row and column offsets. For each starting cell and each offset, begin with `value = 0`, append the current digit with `value = value * 10 + mat[row][column]`, and then advance by the same offset. This produces every intermediate number on the path and makes a direction change impossible.

**Count primes as they appear.** Once a generated value is greater than `10`, test whether it is prime and increment its frequency when it is. Different paths may generate the same number, and every occurrence must contribute. Cache primality results because repeated matrix patterns often create the same value many times. Trial division needs only odd divisors whose square does not exceed the candidate.

**Apply both ordering rules together.** If at least one qualifying prime was found, maximize the pair `(frequency, prime)`. Lexicographic maximization first chooses the greatest frequency and then, among ties, the greatest prime.

Every legal generated number belongs to one starting cell, one fixed direction, and one stopping point. The traversal for that start and direction visits the stopping point and forms exactly that number, so no legal candidate is missed. Conversely, every value counted by the algorithm comes from such a traversal and is counted only after passing both the strict `> 10` condition and a correct primality test. Maximizing `(frequency, prime)` therefore returns exactly the result required by the frequency and tie-breaking rules.

## Complexity detail

Let $m$ and $n$ be the matrix dimensions, let $\ell=\max(m,n)$, and let $V$ be the greatest generated value. The eight directions are a constant, and each start-direction traversal contains at most $\ell$ cells. There are $O(mn\ell)$ generated values. A previously unseen value takes $O(\sqrt V)$ time to test for primality, giving the worst-case bound $O(mn\ell\sqrt V)$. The frequency map and primality cache contain at most $O(mn\ell)$ distinct values, which is also the auxiliary-space bound.

## Alternatives and edge cases

- **Sieve of Eratosthenes:** Precomputing all primes up to the largest possible six-digit value supports constant-time checks, but it allocates and initializes a much larger table than the number of values generated by a $6\times6$ matrix.
- **Recount a generated list:** Storing every value and rescanning the list for each prime is correct but can take quadratic time in the number of generated values.
- **Recursive rays:** A recursive function can extend each start-direction pair, but the iterative traversal represents the fixed direction and boundary condition more directly.
- **One cell:** Only a one-digit number is generated, so no value is strictly greater than `10` and the answer is `-1`.
- **Prime `7` or another one-digit prime:** It is excluded by the strict threshold even though it is mathematically prime.
- **Direction changes:** A sequence requiring a turn is never a valid path and must not contribute a number.
- **Reverse directions:** East and west, or any opposite pair, are distinct paths and can generate different numbers such as `13` and `31`.
- **Frequency tie:** The numerically largest prime wins, even if it is encountered earlier or later than the others.
