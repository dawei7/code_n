# Guided Example: Find the Difference

We trace the step-by-step multiset frequency inventory decrement (`cnt[c] -= 1`), negative inventory surplus detection (`cnt[c] < 0`), non-trivial duplicate character resolution, and the dual XOR parity cancellation principle on representative string instances:

- **Input:** $s = \text{"abcd"}, \quad t = \text{"abcde"}$
- **Required output:** `"e"`
  - Initial frequency inventory from $s$: `{'a': 1, 'b': 1, 'c': 1, 'd': 1}`
  - Step 1: $c = \text{'a'} \implies cnt[\text{'a'}] = 1 - 1 = 0 \ge 0$ (Matched)
  - Step 2: $c = \text{'b'} \implies cnt[\text{'b'}] = 1 - 1 = 0 \ge 0$ (Matched)
  - Step 3: $c = \text{'c'} \implies cnt[\text{'c'}] = 1 - 1 = 0 \ge 0$ (Matched)
  - Step 4: $c = \text{'d'} \implies cnt[\text{'d'}] = 1 - 1 = 0 \ge 0$ (Matched)
  - Step 5: $c = \text{'e'} \implies cnt[\text{'e'}] = 0 - 1 = -1 < 0 \implies$ Extra letter identified: $\mathbf{\text{"e"}}$
- **Duplicate Letter Added:** $s = \text{"a"}, t = \text{"aa"}$
  - $cnt = \{\text{'a'}: 1\}$
  - First `'a'`: $cnt[\text{'a'}] = 0 \ge 0$
  - Second `'a'`: $cnt[\text{'a'}] = -1 < 0 \implies$ Returns `"a"`
- **Empty Base String:** $s = \text{""}, t = \text{"y"} \implies cnt[\text{'y'}] = -1 < 0 \implies \text{"y"}$

This instance demonstrates finding a multiset difference via inventory accounting and algebraic cancellation, mathematically proves why bitwise XOR $(\bigoplus s \oplus \bigoplus t)$ yields the exact missing character code in $O(1)$ space, and analyzes $O(N)$ linear runtime bounds.

---

## 1. Instance & Teaching Goal

Given two strings $s = \text{"abcd"}$ and $t = \text{"abcde"}$ where $t$ is generated by randomly shuffling $s$ and adding one more letter at a random position:
Find the letter that was added to $t$:

```text
String s: "abcd"   (Length 4)
String t: "abcde"  (Length 5 = 4 + 1)

Inventory matching:
  s supplies: {'a': 1, 'b': 1, 'c': 1, 'd': 1}
  t consumes: 'a' (OK), 'b' (OK), 'c' (OK), 'd' (OK), 'e' (DEFICIT!)

Extra character: 'e'
```

### The Inadequacy of Set Difference
If $s = \text{"a"}$ and $t = \text{"aa"}$, the added character is `'a'`, which is already present in $s$. A standard mathematical set `{a}` would fail to distinguish the strings because `set(t) == set(s)`. We must account for **multiset multiplicity**.

---

## 2. Conceptual Foundation & Invariants

### 1. The Frequency Inventory State Machine:
- Construct character frequency map of $s$:
  $$
  cnt = \text{Counter}(s)
  $$
- Iterate through each character $c \in t$:
  - Decrement available supply:
    $$
    cnt[c] \leftarrow cnt[c] - 1
    $$
  - **Deficit Detection:** If $cnt[c] < 0$, string $t$ has consumed more copies of $c$ than $s$ provided. Return $c$ immediately.

### 2. The Dual Mathematical Principle (Bitwise XOR):
Every character present in $s$ appears an even number of times across the union $s \cup t$ (once in $s$ and once in $t$), except the added character which appears an odd number of times (one extra copy in $t$).
By the involution property of XOR ($x \oplus x = 0$ and $x \oplus 0 = x$):
$$
\text{diff} = \bigoplus_{c \in s} \text{ord}(c) \; \oplus \; \bigoplus_{c \in t} \text{ord}(c) = \text{ord}(\text{added letter})
$$

> **Invariant.** After processing prefix $t[0 \dots k]$, $cnt[c] \ge 0$ implies all occurrences of $c$ in the prefix have been successfully matched with copies from $s$. The first character $c$ causing $cnt[c] < 0$ is guaranteed to be the uniquely added character.

---

## 3. Step-by-Step Worked Execution

We trace $s = \text{"abcd"}, t = \text{"abcde"}$:

---

### Step 1: Initial Frequency Counting of $s$
Construct inventory:
$$
cnt = \{\text{'a'}: 1, \; \text{'b'}: 1, \; \text{'c'}: 1, \; \text{'d'}: 1\}
$$

---

### Step 2: Sequential Consumption of Characters in $t$

- **Character 1: $c = \text{'a'}$:**
  - Decrement: $cnt[\text{'a'}] \leftarrow 1 - 1 = \mathbf{0}$.
  - Check $cnt[\text{'a'}] < 0$: False ($0 \ge 0$). Continue.

- **Character 2: $c = \text{'b'}$:**
  - Decrement: $cnt[\text{'b'}] \leftarrow 1 - 1 = \mathbf{0}$.
  - Check $cnt[\text{'b'}] < 0$: False. Continue.

- **Character 3: $c = \text{'c'}$:**
  - Decrement: $cnt[\text{'c'}] \leftarrow 1 - 1 = \mathbf{0}$.
  - Check $cnt[\text{'c'}] < 0$: False. Continue.

- **Character 4: $c = \text{'d'}$:**
  - Decrement: $cnt[\text{'d'}] \leftarrow 1 - 1 = \mathbf{0}$.
  - Check $cnt[\text{'d'}] < 0$: False. Continue.

- **Character 5: $c = \text{'e'}$:**
  - Character `'e'` was not in $s \implies$ initial default count was $0$.
  - Decrement:
    $$
    cnt[\text{'e'}] \leftarrow 0 - 1 = \mathbf{-1}
    $$
  - Check $cnt[\text{'e'}] < 0$: **True** ($-1 < 0$).
  - Deficit detected!
  - Return:
    $$
    \mathbf{\text{"e"}}
    $$

---

## 4. Complete Execution Trace

```text
s = "abcd", t = "abcde"
cnt = {'a': 1, 'b': 1, 'c': 1, 'd': 1}

t[0] = 'a' -> cnt['a'] = 0 >= 0 -> OK
t[1] = 'b' -> cnt['b'] = 0 >= 0 -> OK
t[2] = 'c' -> cnt['c'] = 0 >= 0 -> OK
t[3] = 'd' -> cnt['d'] = 0 >= 0 -> OK
t[4] = 'e' -> cnt['e'] = -1 < 0 -> DEFICIT -> Return "e"
```

| Step | Char $c \in t$ | Inventory Supply Before | Decrement Action | Inventory Supply After | Deficit Condition ($< 0$) | Action Taken |
|:---:|:---:|:---:|:---:|:---:|:---:|:---|
| Init | - | - | Count $s$ | `{'a':1, 'b':1, 'c':1, 'd':1}` | None | Setup complete |
| 1 | `'a'` | 1 | $1 - 1$ | 0 | False | Continue |
| 2 | `'b'` | 1 | $1 - 1$ | 0 | False | Continue |
| 3 | `'c'` | 1 | $1 - 1$ | 0 | False | Continue |
| 4 | `'d'` | 1 | $1 - 1$ | 0 | False | Continue |
| **5** | **'e'** | **0** | **$0 - 1$** | **$-1$** | **True** | **Terminate & Return `"e"`** |

---

### Duplicate Case Comparison ($s = \text{"a"}, t = \text{"aa"}$)

```text
s = "a", t = "aa"
cnt = {'a': 1}

t[0] = 'a': cnt['a'] = 1 - 1 = 0 >= 0 -> OK
t[1] = 'a': cnt['a'] = 0 - 1 = -1 < 0 -> DEFICIT -> Return "a"
```

---

## 5. Algorithmic Correctness

**Soundness.** String $t$ has length $N + 1$ and contains exactly one more character occurrence than $s$ (length $N$). Because $s$ and $t$ match identically on all other $N$ positions regardless of permutation, the count of every matching character will reach 0 after all its occurrences are processed. The extra character in $t$ will inevitably cause its count to drop to $-1$, accurately pinpointing the answer.

**Completeness.** Every character in $t$ is evaluated sequentially. Since exactly one extra character exists by problem precondition, the loop is guaranteed to encounter a negative inventory count and return within at most $N + 1$ steps.

---

## 6. Traps This Instance Exposes

- **Duplicate Characters:** If the extra character is a duplicate of an existing letter (e.g. $s = \text{"a"}, t = \text{"aa"}$), using `set(t) - set(s)` returns an empty set. A frequency counter or XOR accumulator must be used.
- **Fixed Array Optimization:** Using an integer array `int[26]` indexed by `ord(c) - ord('a')` eliminates dictionary overhead.
- **Bitwise XOR Alternative:** An accumulator `ans = 0` XORed with `ord(c)` for all $c \in s + t$ directly evaluates to `chr(ans)`, requiring strictly $O(1)$ memory without any hash map allocations.

---

## 7. Complexity Derivation

- **Time Complexity:** $O(N)$, where $N = \text{len}(s)$.
  - Counting characters in $s$ takes $O(N)$ time.
  - Iterating through $t$ (length $N + 1$) takes $O(N)$ time.
  - Total runtime is strictly linear $O(N)$.
- **Auxiliary Space Complexity:** $O(|\Sigma|) = O(1)$, where $|\Sigma| \le 26$ lowercase English letters, bounding the frequency hash table size.
