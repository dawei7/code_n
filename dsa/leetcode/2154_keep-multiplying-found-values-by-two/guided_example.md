# Guided Example: Keep Multiplying Found Values by Two

We analyze and execute the iterative geometric doubling simulation on a representative problem instance, demonstrating how set membership testing tracks exponential progression until reaching the first absent boundary value.

- **Input:** `nums = [5, 3, 6, 1, 12]`, `original = 3`
- **Output:** `24`

This instance illustrates hash set membership queries, geometric power-of-two state advancement, termination at the first absent value, and invariance to non-target array elements.

---

## 1. Problem Overview & Representative Instance

We are given an integer array `nums` and an initial integer `original`. The simulation follows a deterministic geometric chain:
1. Check whether the current value of `original` is present in `nums`.
2. If present, double the value: $\text{original} \leftarrow 2 \times \text{original}$, and repeat the search.
3. If absent, terminate and return the current value of `original`.

Occurrences in `nums` are not consumed or deleted: duplicate copies of a number in `nums` do not trigger duplicate doublings; only existence matters.

In our representative instance:
- `nums = [5, 3, 6, 1, 12]`
- Starting value: `original = 3`

We must trace the sequence of doublings generated by `nums` until reaching a value not present in the array.

---

## 2. Mathematical & Algorithmic Principles

### The Geometric Progression Subsequence

Let $x_0 = \text{original}$. The sequence of candidate queries forms a strictly increasing geometric progression:
$$x_k = x_0 \cdot 2^k \quad \text{for } k = 0, 1, 2, \dots$$

Let $S$ denote the set of distinct elements present in `nums`:
$$S = \{v \in \text{nums}\}$$

The algorithm seeks the smallest non-negative integer $m$ such that:
$$x_m \notin S \quad \text{while } x_k \in S \text{ for all } 0 \le k < m$$

The return value is $x_m = x_0 \cdot 2^m$.

### Constant-Time Membership via Hash Set

Instead of scanning the array of length $n$ on each doubling ($O(n)$ per step), inserting all elements of `nums` into a hash set enables $O(1)$ expected lookup per query. Because each step doubles the value and elements are bounded by $1000$ (or at most $10^9$), the maximum number of doublings cannot exceed $\lfloor\log_2(M)\rfloor \approx 10$ to $30$ steps.

### Monotonic Sorting Alternative

Because the sequence $x_0, 2x_0, 4x_0, \dots$ is strictly increasing:
- If `nums` is sorted in non-decreasing order, any number matching the current `original` will be encountered in increasing order.
- A single linear scan through sorted `nums` updating $\text{original} \leftarrow 2 \times \text{original}$ whenever $\text{num} == \text{original}$ correctly finds the stopping point in $O(n \log n)$ time and $O(1)$ auxiliary space.

| Step Parameter | Algebraic Expression | Instance Role (`original = 3`) |
|---|---|---|
| Initial Probe $x_0$ | $3 \cdot 2^0$ | $3$ (checks if search begins) |
| Multiplier | $\times 2$ | Doubling factor applied at each match |
| Intermediate State $x_k$ | $x_{k-1} \times 2$ | Tracks active query value |
| Termination Condition | $x_k \notin S$ | Halts loop when candidate is absent from set |
| Final Output | $x_m$ | First missing power of two multiple ($24$) |

## 3. Step-by-Step Walkthrough with Intermediate State

We trace the hash-set simulation on `nums = [5, 3, 6, 1, 12]` starting at `original = 3`.

```
Set S = {1, 3, 5, 6, 12}
Start original = 3

Query 3:  in S? YES => original = 3 * 2 = 6
Query 6:  in S? YES => original = 6 * 2 = 12
Query 12: in S? YES => original = 12 * 2 = 24
Query 24: in S? NO  => STOP! Return 24
```

### Step 1: Populate Hash Set
Convert `nums = [5, 3, 6, 1, 12]` into set $S$:
$$S = \{1, 3, 5, 6, 12\}$$
Size of set $|S| = 5$.

### Step 2: Query $k = 0$ (Candidate: $x_0 = 3$)
- Current probe: $3$.
- Query set: Is $3 \in S$?
  - Present: True.
- Action: Double candidate value:
  $$\text{original} \leftarrow 3 \times 2 = 6$$
- State: $1$ match found, loop continues.

### Step 3: Query $k = 1$ (Candidate: $x_1 = 6$)
- Current probe: $6$.
- Query set: Is $6 \in S$?
  - Present: True.
- Action: Double candidate value:
  $$\text{original} \leftarrow 6 \times 2 = 12$$
- State: $2$ matches found, loop continues.

### Step 4: Query $k = 2$ (Candidate: $x_2 = 12$)
- Current probe: $12$.
- Query set: Is $12 \in S$?
  - Present: True.
- Action: Double candidate value:
  $$\text{original} \leftarrow 12 \times 2 = 24$$
- State: $3$ matches found, loop continues.

### Step 5: Query $k = 3$ (Candidate: $x_3 = 24$)
- Current probe: $24$.
- Query set: Is $24 \in S$?
  - Present: False ($24 \notin \{1, 3, 5, 6, 12\}$).
- Action: Absence detected. Terminate simulation.
- Return final value: $24$.

## 4. Comprehensive State Trace

The table below catalogs every query in the doubling sequence:

| Step $k$ | Candidate Value $x_k$ | Formula | Present in Set $S$? | Operation Executed | Next Candidate $x_{k+1}$ | Continuation Status |
|---|---|---|---|---|---|---|
| $0$ | $3$ | $3 \cdot 2^0$ | Yes ($3 \in S$) | Double ($3 \times 2$) | $6$ | Continue |
| $1$ | $6$ | $3 \cdot 2^1$ | Yes ($6 \in S$) | Double ($6 \times 2$) | $12$ | Continue |
| $2$ | $12$ | $3 \cdot 2^2$ | Yes ($12 \in S$) | Double ($12 \times 2$) | $24$ | Continue |
| $3$ | $24$ | $3 \cdot 2^3$ | **No** ($24 \notin S$) | Terminate | - | **Terminated** |

Final value returned: $24$.

### Sorted Array Scan Alternative Trace

Tracing with sorted array `nums = [1, 3, 5, 6, 12]` and `original = 3`:
- Element $1$: $1 \ne 3$. (Skip)
- Element $3$: $3 == 3$. Update $\text{original} \leftarrow 3 \times 2 = 6$.
- Element $5$: $5 \ne 6$. (Skip)
- Element $6$: $6 == 6$. Update $\text{original} \leftarrow 6 \times 2 = 12$.
- Element $12$: $12 == 12$. Update $\text{original} \leftarrow 12 \times 2 = 24$.
- End of array reached. Final value: $24$.

Both approaches confirm identical termination at $24$.

## 5. Algorithmic Correctness & Soundness

### Termination Guarantee
Because `nums` is finite with at most $n$ elements, the maximum value in `nums` is bounded by $M = \max(\text{nums})$. The sequence $x_k = x_0 \cdot 2^k$ is strictly increasing. Once $x_k > M$, it is impossible for $x_k$ to belong to `nums`. Thus the loop is guaranteed to terminate in at most:
$$k \le \left\lfloor \log_2\left(\frac{M}{x_0}\right) \right\rfloor + 1 \text{ steps}$$

### Uniqueness of Stopping State
At every step $k < m$, $x_k$ was verified to belong to `nums`. At step $m$, $x_m$ is verified to be absent from `nums`. Thus $x_m$ is the unique first value in the doubling sequence that does not appear in `nums`.

---

## 6. Edge Cases & Anti-Patterns

### Edge Cases
1. **Initial Value Absent ($x_0 \notin \text{nums}$):** If `original = 4` and `nums = [2, 7, 9]`, $4 \notin S$. The loop executes zero iterations and immediately returns $4$.
2. **Multiple Duplicates in Array:** `nums = [3, 3, 3, 6, 6]`, `original = 3`.
   - $3 \in S \implies \text{original} = 6$.
   - $6 \in S \implies \text{original} = 12$.
   - $12 \notin S \implies \text{returns } 12$. Set deduplication naturally ignores multiple copies.
3. **Single Element Matching:** `nums = [5]`, `original = 5`.
   - $5 \in S \implies \text{original} = 10$.
   - $10 \notin S \implies \text{returns } 10$.

### Common Anti-Patterns
- **Repeated Linear Search ($O(k \cdot n)$):** Searching `nums` with `x in nums` on each doubling scans the entire list repeatedly, costing $O(k \cdot n)$ time. Building a hash set up front reduces queries to $O(1)$.
- **Consuming Elements:** Deleting found elements from `nums` is unnecessary because each queried value $x_k$ is strictly greater than all previous queried values $x_0, \dots, x_{k-1}$, so no previously matched value is ever queried again.
- **Premature Halting:** Halting before testing whether the doubled value itself exists in `nums` produces off-by-one doubling errors.

---

## 7. Complexity Analysis

### Time Complexity
- **Set Construction:** Inserting $n$ elements into a hash set takes $O(n)$ time.
- **Doubling Loop:** Each doubling multiplies the value by $2$. For values bounded by $M \le 1000$ (or $10^9$), the loop runs at most $O(\log(M / \text{original}))$ times.
- Each set lookup takes $O(1)$ expected time.
- Total time complexity is $O(n + \log M)$, which takes less than $1$ millisecond for $n = 1000$.

### Auxiliary Space Complexity
- The hash set stores up to $n$ unique integers.
- Total auxiliary space complexity is $O(n)$ (or $O(1)$ if sorting in place).
