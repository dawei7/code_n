## General

**The perfect-square condition is about prime-exponent parity.** Write a positive index as a prime factorization. A number is a perfect square exactly when every prime exponent is even. For two indices $i$ and $j$, the exponent of each prime in $ij$ is the sum of its exponents in $i$ and $j$. That sum is even for every prime precisely when $i$ and $j$ have the same pattern of odd exponents.

That pattern is often called the square-free kernel. Remove every square factor from an index; what remains is the product of primes whose exponents were odd. For example, $8=2\cdot2^2$ has kernel $2$, $18=2\cdot3^2$ also has kernel $2$, and $2\cdot8=16$ is a square. By contrast, indices with different kernels cannot multiply to a square.

Therefore, a complete subset consists of indices sharing one square-free kernel. For a kernel $k$, all such indices have the form

$$
k\cdot j^2
$$

for positive integers $j$ within the array bounds.

**How the exact solution enumerates these families.** The outer loop tries every `k` from `1` through `n`. For that `k`, the inner loop starts `j = 1` and visits indices $k,4k,9k,16k,\ldots$ while `k * j * j <= n`. Because the problem uses one-based indices but Python lists are zero-based, value at problem index `k * j * j` is read as `nums[k * j * j - 1]`. The variable `t` accumulates the values at all visited indices, and `ans` retains the largest accumulated sum.

Any two visited indices are $ka^2$ and $kb^2$. Their product is

$$
(ka^2)(kb^2)=k^2a^2b^2=(kab)^2,
$$

which is a perfect square. Thus every candidate generated by the inner loop is a valid complete subset.

**Why trying non-square-free `k` does not break correctness.** The loop does not restrict `k` to square-free numbers. If `k = q r^2` with square-free kernel $q$, indices `k * j * j = q * (rj) * (rj)` form only a subset of the full family for $q$. This duplicates some work, but it cannot create an invalid candidate.

Could such a partial family incorrectly win? No, because every `nums[i]` is positive. The full square-free-kernel family contains every value in the partial family plus possibly more positive values, so its sum is at least as large. The outer loop eventually tries the square-free kernel $q$ itself and evaluates that full family. Consequently, redundant non-square-free values of `k` cannot cause the maximum to be wrong.

**Why every optimum is covered.** All indices of any legal complete subset have the same square-free kernel $q$. Since values are positive, once that kernel is chosen there is never a reason to omit another in-range index with the same kernel: adding it preserves the pairwise perfect-square property and increases the sum. Therefore an optimal subset is the full family `q * j * j`. The iteration with `k = q` computes exactly its sum, so the global maximum includes the optimum.

For the first example, `k = 2` visits one-based indices `2` and `8` because they are `2*1*1` and `2*2*2`. Their values are `7` and `9`, summing to `16`. Their index product is `16`, a perfect square.

## Complexity detail

For a fixed `k`, the inner loop runs $\lfloor\sqrt{n/k}\rfloor$ times. Total iterations are

$$
\sum_{k=1}^{n}\left\lfloor\sqrt{\frac nk}\right\rfloor
\le
\sqrt n\sum_{k=1}^{n}\frac1{\sqrt k}.
$$

The sum $\sum_{k=1}^{n}k^{-1/2}$ is $O(\sqrt n)$, so the product is $O(n)$. The nested loops may look quadratic, but the inner ranges shrink quickly enough for total $O(n)$ time.

Only `ans`, `t`, `k`, and `j` are stored. No kernel table or list of groups is allocated, so auxiliary space is $O(1)$. Arithmetic uses Python integers, which safely hold sums up to roughly $10^{13}$ under the constraints. The input is not modified.

## Alternatives and edge cases

- **Explicit square-free kernels:** Factor every index, compute its kernel, and accumulate values in a map keyed by that kernel. This is direct but needs extra storage and factorization machinery.
- **Sieve-based kernels:** A smallest-prime-factor sieve can derive kernels efficiently, yet $O(n)$ extra memory is unnecessary for the square-multiple enumeration.
- **Non-square-free outer values:** They generate redundant partial families, not incorrect families. Positivity ensures a partial family never beats its full kernel group.
- **One-based indexing:** The mathematical index is `k*j*j`; subtract one exactly once when reading `nums`.
- **Single element:** `k = 1` and `j = 1` visit the only value, and a one-element subset vacuously satisfies the pair condition.
- **Positive-values guarantee:** The proof that a full kernel group is best relies on all values being positive. With negative values, choosing a beneficial subset would require additional reasoning.
- **Large sums:** A 64-bit integer is needed in fixed-width languages because up to $10^4$ values of size $10^9$ may be added.
- **Pairwise condition:** Sharing a kernel simultaneously guarantees the condition for every pair; checking only adjacent chosen indices would not generally be a sufficient formulation.
