# Quadratic Primes - Optimal Approach

## 1. Problem Essence & Formal Mathematical Formulation

Consider the quadratic formula:
$$P_{a,b}(n) = n^2 + an + b \quad \text{where } |a| < 1000 \text{ and } |b| \le 1000 \quad (a, b \in \mathbb{Z})$$

Let $N(a, b)$ denote the number of consecutive prime values generated by $P_{a,b}(n)$ starting from $n = 0$:
$$N(a, b) = \min \{ n \in \mathbb{N}_0 \mid P_{a,b}(n) \notin \mathbb{P} \}$$

The objective is to find the product of the coefficients $a \cdot b$ for the quadratic expression that produces the maximum number of consecutive primes:
$$\text{Product} = a_{\text{max}} \cdot b_{\text{max}}, \quad \text{where } (a_{\text{max}}, b_{\text{max}}) = \operatorname*{arg\,max}_{|a| < 1000, |b| \le 1000} N(a, b)$$

---

## 2. The Naive Approach & Fundamental Bottlenecks

### Unconstrained 2D Parameter Search
A naive algorithm searches all pairs $(a, b) \in [-999, 999] \times [-1000, 1000]$ (nearly $4 \times 10^6$ combinations) and checks primality from scratch:
```python
def naive_quadratic_primes():
    for a in range(-999, 1000):
        for b in range(-1000, 1001):
            # tests all 4 million pairs
            # ...
```

### Computational Inefficiencies
1. **$96\%$ Redundant Search Space**: 
   - At $n = 0$, $P_{a,b}(0) = b \implies b$ must be a prime number in $[2, 1000]$.
   - At $n = 1$, $P_{a,b}(1) = 1 + a + b \implies a$ must be an odd integer when $b > 2$.
2. **Repeated Primality Factorization**: A precomputed boolean sieve array up to $200\,000$ enables $\mathcal{O}(1)$ prime testing.

## 3. Core Intuition & Mathematical Structure

### Necessary Mathematical Constraints

| Parameter / Constraint | Mathematical Derivation | Search Domain Impact |
| :--- | :--- | :--- |
| **Primality of $b$** | $P_{a,b}(0) = 0^2 + a(0) + b = b \in \mathbb{P}$ | $b \in \mathbb{P}_{\le 1000}$ ($168$ primes) |
| **Parity of $a$** | For odd prime $b$, $1 + b$ is even. For $1 + a + b$ to be odd prime, $a$ must be odd | $a \in \{-999, -997, \dots, 999\}$ ($1000$ values) |
| **Upper Bound on Chain** | $P_{a,b}(b) = b^2 + ab + b = b(b + a + 1)$ is divisible by $b$ | $N(a, b) \le b$ |

### Notable Quadratic Prime Generators

| Polynomial $n^2 + an + b$ | $(a, b)$ | Consecutive Primes Generated $N(a, b)$ | Prime Range Produced |
| :---: | :---: | :---: | :--- |
| $n^2 + n + 41$ (Euler) | $(1, 41)$ | $40$ primes ($n = 0 \dots 39$) | $41, 43, 47, \dots, 1601$ |
| $n^2 - 79n + 1601$ | $(-79, 1601)$ | $80$ primes ($|b| > 1000$) | $1601, 1523, \dots, 41$ |
| $n^2 - 61n + 971$ | **$(-61, 971)$** | **$71$ primes** ($n = 0 \dots 70$) | $971, 911, 853, \dots, 1601$ |

## 4. Rigorous Mathematical Breakthrough & Derivations

### Sieve-Accelerated Exploration
1. Precompute a boolean sieve $\mathbf{S}$ of primes up to $200\,000$.
2. Filter $b \in \mathbb{P}_{\le 1000}$ ($168$ primes).
3. For each $b$, iterate odd $a \in [-999, 999]$ (with step $2$).
4. Count consecutive primes $P_{a,b}(n) = n^2 + an + b$ while $\mathbf{S}[P_{a,b}(n)] == \text{True}$.
5. Track and update maximum chain length $N_{\text{max}}$ and product $a \cdot b$.

---

## 5. Concrete Step-by-Step Example Walkthrough

### Example 1: Euler's Polynomial $n^2 + n + 41$
- $a = 1, b = 41$.
- $n = 0 \implies 41$ (prime)
- $n = 1 \implies 1 + 1 + 41 = 43$ (prime)
- $\dots$
- $n = 39 \implies 39^2 + 39 + 41 = 1601$ (prime)
- $n = 40 \implies 40^2 + 40 + 41 = 40(41) + 41 = 41 \times 41 = 1681 = 41^2$ (composite).
- Generates **$40$** consecutive primes! $\checkmark$

### Example 2: Target Evaluation for $|a| < 1000, |b| \le 1000$
- At $a = -61, b = 971$:
  - $n = 0 \implies 971$ (prime)
  - $n = 1 \implies 911$ (prime)
  - $\dots$
  - $n = 70 \implies 70^2 - 61(70) + 971 = 1601$ (prime)
  - $n = 71 \implies 71^2 - 61(71) + 971 = 71(10) + 971 = 1681 = 41^2$ (composite).
  - Consecutive primes: $N(-61, 971) = \mathbf{71}$.
- Coefficient Product:
  $$a \cdot b = -61 \times 971 = \mathbf{-59\,231}$$

## 6. Implementation Architecture & Algorithmic Blueprint

### Algorithmic Execution Pipeline

| Stage | Operation | Code / Formula Action | Complexity |
| :---: | :--- | :--- | :---: |
| **Stage 1** | **Boolean Sieve** | Precompute primes up to $200\,000$ | $\mathcal{O}(M \log \log M)$ |
| **Stage 2** | **Filter $b$** | `b_primes = [b for b in range(2, 1001) if is_prime(b)]` | $168$ primes |
| **Stage 3** | **Odd $a$ Search** | For $b \in \text{primes}$, for $a \in [-999, 999]$ step $2$ | $168 \times 1000$ pairs |
| **Stage 4** | **Chain Length** | `while is_prime(n*n + a*n + b): n += 1` | $\mathcal{O}(1)$ per step |
| **Stage 5** | **Return Product** | Return scalar integer $-59231$ | $\mathcal{O}(1)$ |

## 7. Mathematical Complexity & Edge Case Invariants

| Dimension | Complexity | Performance / Resource Bounds |
| :--- | :--- | :--- |
| **Time Complexity** | $\mathcal{O}(\pi(L) \cdot L \cdot N_{\text{max}})$ | $\approx 0.025$ seconds for $L = 1000$ |
| **Space Complexity** | $\mathcal{O}(M)$ where $M = 200\,000$ | Sieve array $\approx 200$ KB |
| **Dynamic Execution** | $100\%$ Inline | Fast sieve array lookup |

### Critical Invariants & Edge Cases Handled:
1. **Negative Value Guard**: $n^2 + an + b$ can be negative for certain $a < 0$; the primality helper checks $v > 1$ before array lookup.
2. **Even Prime $b = 2$**: Special handling tests even step or negative values when $b = 2$.
