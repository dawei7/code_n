# Longest Collatz Sequence - Optimal Approach

## 1. Problem Essence & Formal Mathematical Formulation

Let $f : \mathbb{N} \to \mathbb{N}$ denote the piecewise Collatz function:
$$f(n) = \begin{cases} n / 2 & \text{if } n \equiv 0 \pmod 2 \\ 3n + 1 & \text{if } n \equiv 1 \pmod 2 \end{cases}$$

The Collatz sequence generated by starting seed $n_0 \in \mathbb{N}$ is the sequence of iterates $(n_0, n_1, n_2, \dots)$ where $n_{k+1} = f(n_k)$.

Let $L(n)$ denote the total chain length (including starting value and final $1$):
$$L(1) = 1, \quad L(n) = 1 + L(f(n)) \quad \text{for } n \ge 2$$

The objective is to compute the starting seed $n_0 < 1\,000\,000$ that produces the longest chain:
$$n_{\text{max}} = \operatorname*{arg\,max}_{1 \le n_0 < 1\,000\,000} L(n_0)$$

---

## 2. The Naive Approach & Fundamental Bottlenecks

### Unmemoized Traversal
A naive algorithm steps through $f(n)$ until reaching $1$ for each starting number independently:
```python
def collatz_length(n):
    length = 1
    while n > 1:
        n = n // 2 if n % 2 == 0 else 3 * n + 1
        length += 1
    return length
```

### Computational Inefficiencies
1. **Redundant Traversal of Shared Tails**: Collatz trajectories constantly merge into previously evaluated paths. For instance, $n = 26 \to 13$, recomputing the full 10-step sequence of $13$.
2. **Double Testing Lower Halves**: For any $k < 500\,000$, $2k < 1\,000\,000$ has length $L(2k) = 1 + L(k) > L(k)$, making testing $k < 500\,000$ unnecessary for finding the global maximum.

---

## 3. Core Intuition & Mathematical Structure

### Upper-Half Dominance Lemma
For any integer $k < \lfloor N / 2 \rfloor$:
$$2k < N \implies f(2k) = k \implies L(2k) = 1 + L(k) > L(k)$$
**Theorem:** The global maximum starting value in $[1, N-1]$ cannot lie in $[1, N/2 - 1]$. The search space is strictly halved to $n_0 \in [N/2, N-1]$.

## 4. Rigorous Mathematical Breakthrough & Derivations

### Memoized Dynamic Programming
Define memo table $\mathcal{M}$ mapping evaluated numbers to their chain lengths:
$$L(n) = \begin{cases} \mathcal{M}[n] & \text{if } n \in \mathcal{M} \\ 1 + L(n/2) & \text{if } n \text{ is even} \\ 1 + L(3n + 1) & \text{if } n \text{ is odd} \end{cases}$$

Storing intermediate lengths turns recurring path traversals into $\mathcal{O}(1)$ lookups, reducing total runtime to under $0.5$ seconds for $N = 10^6$.
